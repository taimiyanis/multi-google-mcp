How it works Setup GitHub

One MCP server for all your Gmail accounts.

Claude reads every inbox you have, drafts replies from the right address, tidies your mail and checks every calendar. It never sends and never deletes. Open source, and it runs on your machine.

$ git clone https://github.com/taimiyanis/multi-mail-mcp.git $ cd multi-mail-mcp && npm install $ npm run setup

What you ask

  • What came in today across my inboxes?
  • Summarise the thread with the venue about Thursday and draft a reply from my work address.
  • Who have I been waiting on for more than three days?
  • Archive the newsletters and label the client emails. You see the plan first.
  • Am I free Thursday afternoon, on any calendar?

A morning with /mail-triage

One command in Claude Code. It reads what is new in every account, finds the replies you owe and the answers you are waiting for, and leaves drafts in each account, written the way you write.

How it works

Tools

ToolDoes
search_mailGmail search syntax, across every account or one
read_threadA whole thread as plain text, with attachment names
create_draftA reply in the thread, or a new email, saved as a draft in the chosen account
label_threadsApply or remove labels; missing labels are created
archive_threadsOut of the inbox, still in All Mail, back on any reply
mark_readRead or unread
list_eventsEvery calendar of every account, duplicates merged
list_accounts, list_labelsWhat is connected, and each account's labels

Safety, by design

  • No send, no delete. Those tools do not exist. Every email leaves from your own Gmail, after you have read it.
  • Everything is reversible. Archived mail stays in All Mail and returns on a reply. Labels come off. Sorting asks first until you tell it not to.
  • Your key, your machine. You create your own Google login key. Tokens stay in ~/.config/multi-mail-mcp, readable by your user only. No third party ever sees your mail.
  • Calendars are read-only. It can tell you when you are free. It cannot book anything.

Setup

Node.js 20 or newer, a Google account, and Claude Code (Claude Desktop and Cursor work too). About 15 minutes, once.

  1. Install

    $ git clone https://github.com/taimiyanis/multi-mail-mcp.git $ cd multi-mail-mcp && npm install

  2. Create your Google login key

    Run npm run setup. It walks you through five screens in Google Cloud, with a link for each: create a project, turn on Gmail and Calendar, set up the sign-in screen, publish it, and create a Desktop app client. Then you paste the ID and secret.

  3. Connect your accounts

    Type each address. A browser tab opens for each one. Google warns that the app is not verified: it is your own private app, so choose Advanced, then Go to your app, and tick every box.

  4. Connect Claude

    Setup registers the server in Claude Code for all your projects and installs the /mail-triage skill. Open a new session and ask what came in today.

Questions

Why do I need my own Google project?

Reading Gmail is a restricted permission. An app that many people share needs a paid, yearly security audit from Google. A private app used only by you does not, and your mail never touches anyone else's server.

Google says "Access blocked: admin_policy_enforced".

That organisation's Google admin blocks outside apps. Only the admin can allow it. Your other accounts still work.

Why does the consent screen mention sending?

Archiving and labelling need Gmail's "modify" permission, and Google describes that permission broadly. The server exposes no send tool, and the code is open for you to check.

Does it work with Outlook or iCloud?

Not yet. Gmail and Google Workspace accounts only.

How is it different from other Gmail MCP servers?

Several let you switch between accounts. This one is built for doing your email with an assistant: drafts land in the right account and thread, sorting is safe and reversible, calendars are included, and the triage skill learns how you write.
